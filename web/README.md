# Fit Ruler 웹 (A 화면과 사용성)

화면 세 개(입력 → 티셔츠 선택 → 결과)와 서버 없이도 화면을 개발할 수 있는 가짜 API가 들어 있다. A1에서 뼈대를, A2에서 입력 검사·재는 법 안내·핏 리포트 표시를 만들었다. 화면 설계는 [`docs/ux/wireframes.md`](../docs/ux/wireframes.md)를 따른다. 요청·응답 형식은 팀 계약 [`docs/api/`](../docs/api/README.md)(B1·B2)를 따른다.

## 실행

Node.js 20 이상이 필요하다.

```bash
cd web
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 연다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm test` | 가짜 API를 팀 계약 예시(`docs/api/examples`)와 비교하는 테스트 |
| `npm run lint` | ESLint (경고도 실패로 본다) |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 타입 검사 후 배포용 빌드 |

CI(`.github/workflows/ci.yml`의 `web` job)가 lint·타입 검사·테스트·빌드를 돌린다.

## API

형식은 `src/api/types.ts`에 팀 계약 스키마를 그대로 옮겨 두었다. 필드 이름(`height_cm`, `chest_girth_cm` 등)과 값을 바꾸지 않는다.

| 요청 | 응답 | 서버 |
|---|---|---|
| `GET /api/garments` | `GarmentList` (READY 의류, `is_demo`) | B2 |
| `POST /api/fit` | `FitReport` (3D·AI 없이 즉시) | B2 |
| `POST /api/fittings` | `FittingStatus` (3D·실사화 작업, `realize_consent`) | B3 |
| `GET /api/fittings/{job_id}` | `FittingStatus` (단계별 상태·산출물 ID) | B3 |
| `GET /api/artifacts/{artifact_id}` | 산출물 파일 | B3 |

- **오류:** 모두 `ApiErrorBody {code, safe_message, fields}`다. 화면에는 `safe_message`와 `fields[].message`를 그대로 보여 준다.
- **결과 화면이 데이터를 받는 곳:** 핏 리포트는 `POST /api/fit`에서, 3D·실사화 진행은 `/api/fittings`에서 받는다. 작업 서버에 닿지 못해도 핏 리포트는 나온다. 이때 진행 상태 자리에는 "3D·실사 진행 상태를 받지 못해 핏 리포트만 보여 드립니다"라는 안내가 나온다.
  - 리포트만 보여 주는 경우는 작업 API에 닿지 못할 때(경로 없음 404, 연결 안 됨)뿐이다. `POST /api/fittings`가 422·409·500 등으로 실패하면 티셔츠 선택 화면에 오류를 보여 준다(`isFittingApiMissing`, `src/api/api.ts`).

## 가짜 API와 실제 서버

기본은 가짜 API(`src/mocks/`)다. 가짜 API가 하는 일은 다음과 같다.

- **의류 5벌:** 첫 벌은 팀 저장소 `data/garments/tee_regular_m_navy_v1.json`과 같고, 세 벌은 화면 개발용 시연 의류다. 마지막 한 벌은 AI Hub 변환 의류와 **모양만** 같은 합성 의류다(핏형·사이즈 `unknown`, 실측, 총장 없음, 허리 위치 미확인, 원단·`color_hex` 있음). 값과 ID는 지어낸 것이고 AI Hub 값을 옮기지 않았다.
- **핏 계산:** B2 계산기와 기준표 `config/fit_rules_v0.yaml`을 옮겨서 한다. 팀 예시 요청으로 계산한 결과가 `docs/api/examples/fit_report.json`과 같은지 테스트한다. 기준표가 바뀌면 `src/mocks/fit.ts`도 고친다.
- **입력 오류:** 서버와 같은 형식과 문구로 돌려준다. 범위 밖은 422 `INPUT_INVALID`, 없는 의류는 404 `GARMENT_NOT_FOUND`다.
- **3D·실사화 단계:** 몇 초씩 걸려 진행되는 것처럼 보여 준다(몸 생성 2초 → 착장 3초 → 렌더 2초 → 실사화 4초 → 검증 1초). `realize_consent`가 false면 렌더까지만 하고 성공으로 끝낸다.

실제 서버를 쓰려면 저장소 맨 위에서 핏 API를 띄우고, `web/.env`를 만들어 `VITE_USE_MOCK=false`로 둔다. 개발 서버가 `/api`를 `http://127.0.0.1:8000`으로 넘기므로 CORS 설정은 필요 없다.

```bash
uvicorn server.app:app --reload   # 저장소 맨 위에서
```

### 실패 화면 확인

티셔츠 선택 화면 주소 뒤에 `?mockFail=단계`를 붙이고 핏 보기를 누르면 그 단계가 실패한다.

```text
http://localhost:5173/garments?mockFail=realize
```

단계 이름은 `body`, `drape`, `render`, `realize`, `validate` 중 하나다.

### 서버가 치수를 거절하는 화면 확인

티셔츠 선택 화면 주소 뒤에 `?mockReject=칸`을 붙이고 핏 보기를 누르면, 가짜 API가 그 칸을 422 `INPUT_INVALID`로 거절한다. 화면은 `fields[]`를 칸별 오류로 바꿔 입력 화면으로 돌아간다.

```text
http://localhost:5173/garments?mockReject=shoulder_cm
```

칸 이름은 `height_cm`, `chest_cm`, `waist_cm`, `shoulder_cm`, `arm_length_cm` 중 하나다.

### 진행 상태 조회가 끊기는 화면 확인

티셔츠 선택 화면 주소 뒤에 붙이고 핏 보기를 누른다. 옵션은 작업을 만들 때 읽어 그 작업에 남긴다(결과 화면 주소에는 붙지 않는다). 여러 옵션을 `&`로 함께 쓸 수 있다.

| 주소 | 결과 화면에서 보이는 것 |
|---|---|
| `/garments?mockFlaky=2` | 진행 상태 조회가 처음 2번 연결 오류로 실패한다. "다시 시도하는 중 (1/5)" 안내가 나오고 1초·2초 뒤 다시 불러 이어서 진행한다. `6` 이상이면 5번째 연속 실패에서 멈추고 "다시 불러오기" 버튼이 나온다 |
| `/garments?mockLost=1` | 진행 상태 조회가 404 `JOB_NOT_FOUND`다(서버를 다시 켠 경우). "작업 기록을 찾을 수 없습니다" 안내와 "같은 조건으로 다시 시도"·"다른 티셔츠 고르기"가 나온다. 다시 시도로 만든 새 작업은 정상으로 진행한다 |
| `/garments?mockFail=realize&mockFlaky=2` | 두 경우를 함께 본다 |
| `/garments?mockRequery=realize` | 서버가 같은 요청 ID로 결과를 다시 조회하는 경우(B5)다. 실사화 진행 시간의 절반부터 `attempt_no`가 2가 된다. 한 줄 상태가 "실사화 결과 다시 조회 중(2번째) (4/5)"로, 단계 목록에 "다시 조회 중(2번째)"가 붙고, 끝나면 "조회 2번"이 남는다. 단계 이름은 `mockFail`과 같다 |

`npm run dev`(React StrictMode)에서는 결과 화면이 열릴 때 첫 조회가 두 번 일어나, 처음 실패 2번이 한꺼번에 소진된다. 그래서 `mockFlaky=2`는 "(1/5)"만 잠깐 보인다. 간격이 늘어나는 모습은 `mockFlaky=4`(1/5 → 2/5 → 3/5, 1초·2초·4초)로 본다.

## 입력 검사

규칙은 `src/validation/body.ts`에 있다. 범위와 문구는 서버(`server/errors.py`)와 같게 맞췄다.

| 칸 | 지원 범위(cm, 경계 포함) |
|---|---|
| 키 | 140~210 |
| 가슴둘레 | 60~160 |
| 허리둘레 | 50~160 |
| 어깨너비 | 28~60 |
| 팔길이 | 40~85 |

- **서버와 같은 문구:** 빈칸, 숫자 아님, 범위 밖은 서버와 같은 문구로 칸 바로 아래에 보여 준다(예: "가슴둘레 값은 60~160 cm 사이로 입력해 주세요.").
- **화면에서만 하는 검사**
  - 소수 둘째 자리 이상을 막는다.
  - 범위 밖 값이 m·인치·mm로 잰 값처럼 보이면 cm로 바꾼 값을 알려 준다.
  - 끝의 `cm`와 쉼표 소수점은 받아 준다.
- **다음 버튼:** 모든 칸을 검사하고 첫 오류 칸으로 이동한다. 오류가 보이는 칸은 고치는 즉시 다시 검사한다.
- **서버가 거절하면(422):** `safe_message`를 폼 위에, `fields[].message`를 해당 칸 아래에 보여 준다. 404·409는 티셔츠 선택 화면에 서버 문구로 보여 준다.

재는 법 안내(`src/guides/measureGuides.ts`)는 팀 계약의 측정 위치 표 `docs/decisions.md` "신체 측정 위치 (measure_v1)"를 따른다. 허리는 자연 허리(가장 잘록한 곳), 어깨는 어깨끝 사이 직선 거리, 팔길이는 오른팔 기준이다.

## 핏 리포트 표시

- **맨 위:** 서버가 준 `summary`를 그대로 보여 준다.
- **부위마다:** 판정 배지, 차이(cm), 기준표 구간 중 위치, 서버 설명(`explanation`)을 보여 준다.
  - 배지 이름과 구간 순서는 기준표 `fit_rules_v0`의 label_ko를 `src/labels.ts`에 옮겨 쓴다. 응답에 부위별 한국어 이름이 없기 때문이다.
- **판정하지 않은 부위:** `UNKNOWN`·`NOT_EVALUATED`는 "판정 안 함"과 서버 설명으로 보여 준다.
- **경고:** `warnings`(`DEMO_GARMENT`, `WAIST_NOT_EVALUATED`)는 안내 문구로 바꿔 보여 준다.
- **맨 아래:** 차이 읽는 법(옷 − 몸, 가슴·허리는 둘레끼리, 어깨는 너비끼리)만 둔다. 판정 기준 버전(`rules_version`)은 화면에 보여 주지 않는다.

## 화면 디자인 (v3)

실사용자용으로 다시 만든 화면이다. 컨셉 아트는 `artifacts/concept-art/v3/`(로컬, git 제외)에 있다.

- **톤:** 아이보리 바탕, 차콜 글자, 가는 구분선, 각진 검정 버튼. 결과 화면의 피팅룸과 결과 카드만 중간 밝기 회색 바탕(`--studio-bg`)에 흰 입자와 밝은 샴페인 글자다(글자 대비는 카드 아래쪽 기준 4.5:1 이상).
- **색 대비:** 샴페인(`--accent` #b59a6e)은 아이보리 바탕에서 글자 대비가 약 2.4:1이라 선·점·빛 같은 장식에만 쓴다. 글자와 선택 표시는 진한 브론즈(`--accent-ink` #7a5f3a, 약 5.3:1)나 차콜을 쓴다.
- **화면 순서:** 내 치수 → 티셔츠 → 결과. 치수를 한 번 넣고 여러 벌을 입어 본다.
- **실사화 동의:** 티셔츠 화면의 "실사 사진·회전 영상도 만들기" 스위치다. 기본은 꺼짐이고, 외부 전송 안내 문구를 같이 보여 준다.
- **낮은 화면:** 노트북처럼 창 높이가 1040px 이하이면 피팅룸 무대·결과 카드 사진 칸·입력 화면 3D 카드를 폭과 화면 높이 중 작은 쪽에 맞춰, 카드 전체(아래 4단계 진행 표시까지)가 한 화면에 들어오게 한다(무대 최소 높이 260px). 이때 위 여백과 피팅룸 설명 글자를 조금 줄이고, 아래 진행 표시와 겹치는 '1 / 4'는 뺀다. 더 높은 화면은 원래 크기 그대로다. 1280×600·720·860에서 재서 맞췄다.
- **문구:** 화면에는 사용자에게 필요한 문장만 둔다. 팀 계약·측정 방법 버전(measure_v1)·판정 기준 버전 같은 개발용 문장은 띄우지 않는다. 가짜 API 안내 띠와 서버 단계 기록("진행 기록 자세히 보기": 서버 단계 이름·재조회 횟수·검증 수치)도 화면에서 뺐다. 가짜 API인지는 `VITE_USE_MOCK`로 안다.

### 3D (three.js, `src/three/`)

- **입력 화면:** 머리부터 발끝까지 보이는 3D 마네킹이다. 입력한 치수대로 몸이 다시 만들어지고, 칸을 고르면 그 치수를 재는 곳(키 자·어깨너비 선·가슴/허리 고리·팔길이 선)과 이름표가 진해진다. 끌어서 돌려 볼 수 있다. 키 이름표는 자 왼쪽, 머리 끝 높이에 붙는다. 구도는 자 왼쪽의 키 이름표와 몸 오른쪽 이름표가 잘리지 않는 가장 큰 크기로 잡는다(휴대폰처럼 좁은 화면에서는 마네킹이 조금 작아진다). 3D를 불러오는 동안은 빈 자리이고, 마네킹이 만들어지면 서서히 나타난다.
- **마네킹:** Tripo AI로 만든 흰 무광 디스플레이 마네킹(`src/three/assets/mannequin.glb`, 약 0.5 MB, 꼭짓점 2만 5천·삼각형 5만)이다. 근육 결(가슴·복근·팔·허벅지)과 달걀형 얼굴이 있고, 팔은 몸 옆으로 거의 곧게 내린다. 3D가 처음 필요할 때 워커가 한 번 불러온다.
- **치수에 맞추기(`mannequin.ts`):** 키는 그대로 비례해 늘리고, 몸통은 높이마다 다른 배율로 가슴·허리·엉덩이 둘레를 입력값에 맞춘다(가랑이 아래는 다리 축 기준). 팔은 몸통 배율을 받지 않고 어깨너비만큼 옆으로 옮기고 팔길이만큼 팔 축을 따라 늘인다. 몸통이 굵어져 팔 안쪽과 닿으면 팔을 어깨 관절 기준으로 조금 벌린다. 맞추는 데 약 10 ms 걸린다. 높이 기준(가랑이·허리·겨드랑이·가슴·어깨)과 팔 관절도 이 마네킹에서 잰 값이라, 입력 화면의 키 자·어깨선·가슴/허리 고리·팔길이 선이 마네킹에 맞게 붙는다.
- **마네킹 바꾸기:** Tripo에서 받은 FBX를 `node scripts/convert-mannequin.mjs <파일.fbx> src/three/assets/mannequin.glb`(web 폴더에서)로 바꾼다. 같은 자리 꼭짓점을 합치고 키 1로 맞춘 뒤, 높이별 단면으로 기준 치수를 재고 꼭짓점별 팔 가중치(겨드랑이 아래로 자르면 따로 떨어지는 덩어리 = 팔)를 넣는다. 출력에 찍힌 기준 치수는 `mannequin.ts`의 `MANNEQUIN`에 옮긴다(`mannequin.test.ts`가 GLB와 같은지 확인한다).
- **결과 화면 피팅룸:** 몸은 입력 치수로 맞춘 마네킹, 티셔츠는 핏 리포트의 옷 치수(가슴둘레·어깨너비·소매·총장)로 만든다. 그래서 옷이 크면 헐렁하게, 작으면 붙게 보인다. 꼭 맞는 옷이어도 몸이 옷 밖으로 나오지 않게, 맞춘 마네킹에서 잰 몸통 겉(높이·각도마다 가장 먼 거리)과 팔 겉(팔 축을 따라)보다 6~7 mm 밖까지 옷이 덮는다.
- **모양 만드는 법:** 티셔츠는 SDF에서 표면을 뽑는다(`bodyModel.ts`, `surfaceNets.ts`). 면의 방향은 격자 모서리 양 끝의 안·밖으로 정해 뒤집힌 면(구멍처럼 보이는 곳)이 생기지 않는다. 마네킹 파일을 불러오지 못하면 SDF 몸(근육을 붙인 몸통 + 목·머리·팔·다리)을 대신 쓴다. 웹 워커에서 만들어(`meshWorker.ts`, `meshBuild.ts`) 입력이 멈추지 않는다(이 PC에서 몸과 티셔츠를 합쳐 약 0.3초). 화면용 근사 모양이라 핏 판정에는 쓰지 않는다(판정은 서버 핏 리포트).
- **빛:** 환경 반사 세기는 장면(`scene.environmentIntensity`)에서 낮게 둔다. three r163부터 재질의 `envMapIntensity`는 장면 환경 지도에 걸리지 않아, 재질 값만 낮추면 흰 마네킹이 하얗게 떠서 근육 음영이 사라진다.
- **배경:** 3D 캔버스는 배경을 투명하게 그려(`alpha: true`) 피팅룸 카드 바탕(`--studio-bg`)이 그대로 비친다. 효과 화면과 진행 카드가 한 색으로 이어진다. 빛 번짐(`UnrealBloomPass`)은 원래 섞는 방식이 화면 전체의 알파를 1로 칠해 투명한 배경이 검게 덮이므로, 번짐을 섞을 때 색에만 더하고 알파는 그대로 두게 바꿨다(`StudioEngine.ts`).
- **불러오기:** three.js는 3D가 처음 필요할 때 따로 불러온다. 불러오는 동안은 빈 자리(입력 화면)나 카드 색 그대로인 빈 무대(피팅룸)를 보여 주고, WebGL이 없는 기기(또는 3D를 만들지 못했을 때)에만 2D 그림을 보여 준다.

### 결과 화면

왼쪽은 피팅룸(진행 중) 또는 결과 카드(끝난 뒤), 오른쪽은 핏 리포트다. 핏 리포트는 3D·실사를 기다리지 않고 바로 보인다.

**사용자용 4단계**(`src/progress/steps.ts`). 서버 단계 이름은 화면에 보이지 않는다.

피팅룸 효과는 트리포 AI가 모델을 만들 때처럼, 피팅룸 카드의 회색 바탕 위에서 작고 흰 입자 수만 개가 반짝이며 모양을 이루는 방식이다(`StudioEngine.ts`, `particleShapes.ts`, `materials.ts`).

| 화면 이름 | 서버 단계 | 피팅룸 효과(3D) |
|---|---|---|
| 체형 생성 | BODY_FIT | 입자가 화면 바깥 사방(위·아래·옆·앞뒤)에서 날아와 입력 치수에 맞춘 마네킹 모양 점구름이 된다(대기 중에는 빈 무대). 점구름은 턴테이블에서 천천히 돌며 점점 또렷해진다(치수 이름표는 붙이지 않는다) |
| 가상 착용 | DRAPE | 몸 점구름이 모래알처럼 굳어 흰 마네킹이 되고, 입자가 화면 바깥 사방에서 날아와 고른 옷 치수의 티셔츠 모양으로 마네킹 위에 모인다. 티셔츠는 끝까지 흰 입자로 남는다(옷 색 천으로 굳히지 않는다). 기다리는 동안 밝은 띠가 어깨에서 밑단으로 지나간다 |
| 3D 촬영 | RENDER | 마네킹과 입자 티셔츠가 정면으로 돌아서고, 입자가 사방에서 날아와 둘레에 사진 틀(뷰파인더: 네 귀퉁이 꺾쇠 + 얇은 테두리)을 만든다. 기다리는 동안 빛 띠가 틀 위에서 아래로 되풀이해 훑고, 띠가 지나는 자리의 티셔츠·틀 입자가 반짝인다 |
| 실사 변환 | REALIZE + VALIDATE | 한 번 번쩍인 뒤 모형이 틀 안으로 납작하게 눌려 정면 사진(어두운 회색 바탕, 흰 마네킹 + 입자 티셔츠) 한 장이 되고, 사진 속 사람·옷이 반짝이는 입자로 터지듯 사방으로 흩어진다. 기다리는 동안 입자가 사방에서 날아 돌아와 사진을 다시 채운다(처음 4초에 4분의 1, 나머지는 단계 내내 천천히). 검증 중에는 빛 띠가 지나가고 남은 입자가 모두 돌아온다 |

- **효과 시간:** 실제 단계가 효과보다 빨리 끝나면(가짜 API는 몇 초) 효과를 2.2배 빨리 돌려 따라가고, 단계마다 효과를 끝까지 보여 준다. 새로고침하면 지금 단계부터 시작한다.

- **공통 마네킹이 아닌 내 치수 마네킹:** API 산출물에는 몸만 찍힌 그림이 없어서, 화면이 입력 치수로 직접 마네킹을 만든다. 착장 미리보기가 오면 실제 결과는 그 그림으로 확인한다.
- **사진 카드:** 3D 촬영·실사 변환 단계의 카드는 3D 장면에서 찍은 정면(배경은 비워 두고, 흰 입자가 잘 보이는 어두운 회색 바탕을 따로 깐다)이다. 실제 산출물(착장 미리보기·실사 영상)은 끝난 뒤 결과 카드에서 보여 주고, 같은 시점의 렌더 프레임 위로 빛 커튼이 지나가며 실사로 바뀌는 첫 장면을 한 번 보여 준다.
- **결과 카드 색:** 끝난 뒤 결과 카드(실사 영상 | 3D 미리보기)도 피팅룸과 같은 회색 카드다(탭·안내·4단계 표시도 같은 바탕에 맞춤). 진행 중 카드가 결과 카드로 바뀌어도 한 카드처럼 이어진다. 사진·영상 칸만 렌더와 같은 중간 회색 바탕이다.
- **멈춤:** 단계가 실패하면 그 장면에서 멈추고 흑백으로 어두워진다.
- **예상 시간:** 단계마다 "보통 1분 안팎 걸려요 · 지금 0:42"처럼 보여 준다. 시간은 실제 서버를 이 PC에서 돌린 실측이다(몸 12~20초, 착장 40~430초, 렌더 40~62초, 실사 약 2~3분. 출처는 `STEP_ETA` 주석). 화면이 그 단계를 처음 본 뒤 실측 최대의 1.5배를 넘기면 "평소보다 오래 걸리고 있어요"로 바뀐다.
- **움직임 줄이기:** `prefers-reduced-motion`이면 효과 없이 각 단계의 마지막 모습만 보인다.

**끝난 뒤 결과 칸**(`outcomeOf`)

| 경우 | 보이는 것 |
|---|---|
| 정상 완료 | 실사 영상(없으면 대표 프레임)과 3D 미리보기를 바꿔 본다 |
| 실사화 동의 안 함 | 3D 미리보기와 "실사 영상은 만들지 않았어요" 안내 |
| 3D 촬영·실사 변환에서 멈춤 | 3D 미리보기를 "대체 결과"로, 멈춘 단계와 이유, 다시 시도 |
| 체형 생성·가상 착용에서 멈춤 | 피팅룸에 "○○에서 멈췄어요"와 이유, 다시 시도. 핏 리포트는 그대로 |
| 검증만 실패 | 실사 영상을 보여 주되 "검증을 통과하지 못했어요"로 구분 |
| 핏 리포트만 요청·취소 | 안내 문구 |

## 진행 상태 다시 부르기 (A4)

3D 미리보기는 정지 이미지로만 보여 준다. 웹 3D 뷰어(회전)는 docs/decisions.md "선택 기능"이 정해지지 않아 만들지 않았다.

- **경과 시간:** 서버가 단계별 시각을 주지 않는다. 그래서 피팅룸의 "지금 0:42"는 화면이 그 단계를 처음 본 때부터 브라우저 시계로 잰다(`formatElapsed`, `src/progress/jobSummary.ts`). 작업이 끝나거나 조회가 멈추면 시간도 멈춘다.
- **오류 문구:** 실패한 단계는 오류 코드 안내(`ERROR_LABEL`)로 보여 준다. 표에 없는 코드는 "알 수 없는 오류(코드)"다(`errorText`).
- **다시 부르기**(`src/progress/poller.ts`)
  - 진행 중에는 1초마다 다시 부른다. 실패하면 1초 → 2초 → 4초 …(최대 10초) 뒤 다시 부르고, 성공하면 1초로 돌아간다.
  - 연속 5번 실패하면 멈추고 "다시 불러오기" 버튼을 보여 준다.
  - 404 `JOB_NOT_FOUND`면 바로 멈춘다.
  - 끝난 상태(SUCCEEDED·PARTIAL_SUCCEEDED·FAILED·CANCELLED)면 더 부르지 않는다.
- **실패 뒤 할 일:** 영상 경로가 실패했거나 작업 기록이 없으면 "같은 조건으로 다시 시도"와 "다른 티셔츠 고르기"를 보여 준다.
  - 다시 시도는 티셔츠 선택 화면이 저장해 둔 요청(실사화 동의 포함)을 그대로 `POST /api/fittings`로 보내고 새 작업 주소로 간다(`src/progress/retry.ts`).
  - 저장된 요청이 없으면(새 탭에서 연 결과 등) 다시 시도 버튼은 없다.
- **3D 미리보기**(`src/components/ArtifactImage.tsx`)
  - 불러오는 동안 같은 크기(3:4)의 빈 자리를 둔다.
  - 주소가 열리지 않으면(가짜 어댑터는 `FIT_FAKE_PLACEHOLDERS=1`이 아니면 파일이 없다) "미리보기 파일을 불러오지 못했습니다"를 보여 준다.
  - 누르면 새 탭에서 원본 크기로 연다.
