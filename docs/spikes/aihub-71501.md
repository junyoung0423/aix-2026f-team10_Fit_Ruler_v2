# AI Hub 의류 통합 데이터(dataSetSn 71501) 살펴보기 (C1, #3)

2026-11-11, 준영. Validation 라벨 `VL_상품_상의_t-shirt`(JSON 11,813개)만 봤다. 이미지(원천데이터)는 받지 않았다.
AI Hub 원본(라벨·이미지·설명서)은 저장소에 넣지 않는다. 아래에는 필드 이름과 예시 값만 적는다.

## 근거

- **데이터 설명서(PDF)는 받지 못했다.** 필드 정의는 AI Hub 데이터셋 페이지의 "메타데이터 구조표"와
  값의 범위로 판단했다.
- 구조표에는 필드 이름·자료형·한글 이름·값 목록만 있다. 치수 필드는 단위·측정 방법·기준점 없이 `0~999`로만 적혀 있다.
- 그래서 단면/둘레, 앞길이 기준점, 허리 위치, 소매 시작점은 **설명서로 확인하지 못했다.** 아래 판단 중
  값 범위로 정한 것은 [제안]이다.

## 폴더와 파일

```
VL_상품_상의_t-shirt/
  01_sou_{상품번호 6자리}_{dataset.id 6자리}_{front|back|wear}_02top_02t-shirt_{man|woman}.json
```

- 파일 이름 = `dataset.name` + `.json` (11,813개 모두 확인).
- 상품 번호(예: `000329`)가 의류 ID다. 상품 9,693개. 한 상품에 라벨 1~4개(front·back·wear 사진별)가 있고,
  같은 상품의 라벨은 치수·색·소재·성별이 모두 같다(9,693개 모두 확인).
- `dataset.image_path`·`dataset.label_path`는 한글 폴더 이름이 깨져 있다. 쓰지 않는다.
- 라벨 최상위 키: `dataset`, `annotation`(옷 영역 2D 폴리곤), `metadata.model`(착용 모델), `metadata.clothes`(의류).

## 단면인가 둘레인가 [제안: 둘레]

- 구조표 이름이 "상의가슴둘레"이고, 값이 둘레 범위다. 반팔 라운드넥 상품 3,223개의 가슴 값 중앙값 98 cm(1%~99% 64~128 cm).
  단면이면 성인 반팔은 40~65 cm 정도여야 한다.
- 같은 라벨의 착용 모델 가슴둘레와 비교하면 의류 − 모델이 중앙값 +7 cm(25%~75%: 0~+14 cm)다. 단면이면 약 −40 cm가 나와야 한다.
- 다만 의류 가슴이 모델보다 작은 경우가 22%다(신축성 있는 옷, 몸에 붙는 옷으로 보이나 확인 못 함).
- 그래서 2배 하지 않고 `chest_from_flat_width: false`로 둔다. 설명서에서 단면으로 확인되면
  `--chest-waist-flat-width`로 다시 등록한다.

## 허리

- "상의허리둘레"도 둘레로 본다. 허리 위치가 신체 자연 허리와 대응하는지 근거가 없어 `waist_position_matched: false`
  (핏 리포트에서 허리는 UNKNOWN).
- 반팔 라운드넥 3,223개 중 1,111개(34%)는 허리 = 가슴, 538개(17%)는 허리 = 가슴 = 밑단이다. 따로 재지 않고
  같은 값을 넣었을 수 있다.

## 앞길이

- 구조표에는 "상의앞길이"만 있고 기준점(HPS인지, 앞 목점인지)이 없다. 그래서 `body_length_cm`는 null로 두고
  원래 값을 notes에 적는다. 값 범위는 반팔 라운드넥 중앙값 64 cm(1%~99% 40~78 cm).

어댑터를 반팔 라운드넥 3,223개에 돌린 결과(메모리에서만, 파일 쓰기 없음): **2,303개 READY 변환, 920개 거절**
(여러 색 879, 범위 밖 약 40, 오타 색 이름 `Orenge` 1). 색·섬유에 대소문자만 다른 표기(`gray`, `Regenerated fiber Others`)가
섞여 있어 대소문자는 무시한다.

받는 범위(cm, 경계 포함, [제안]): 가슴 60~200, 허리 50~200, 어깨 25~80, 소매 5~45, 앞길이 35~100.
범위 밖은 단위 오류(mm 등)나 입력 오류로 보고 이유와 함께 거절한다. 예: 어깨 1 cm, 소매 204 cm, 가슴 220 cm.
