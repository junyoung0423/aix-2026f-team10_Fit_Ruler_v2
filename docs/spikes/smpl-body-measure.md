# 스파이크: SMPL 평균 체형 A자세 내보내기와 신체 측정 (D2)

작성 2026-11-10 (2026-11-11 팀 저장소로 옮기며 측정 위치를 measure_v1에 맞춤) · 관련 이슈 #7 · 상태: 코드·합성 몸 검증·**실제 SMPL v1.1.0(중성·남성·여성) 실행 완료**

SMPL 평균 체형을 A자세로 내보내 C의 착장 스파이크 입력(OBJ)으로 넘긴다. 몸 메시에서 신체 치수 5개(키·가슴둘레·허리둘레·어깨너비·팔길이)를 재는 함수도 만든다. 이 함수는 D3에서 사용자 치수에 맞춰 몸을 만들 때 목표값과 비교하는 데 쓴다.

## 1. 구성

| 위치 | 하는 일 |
|---|---|
| `fitting/adapters/smpl/model.py` | SMPL 모델 파일 읽기, 체형(betas)·자세 적용(linear blend skinning), A자세, OBJ 저장. numpy만 쓴다(torch 불필요) |
| `fitting/body/measure.py` | 메시·관절·스키닝 가중치에서 치수 5개를 잰다. 외부 SDK나 어댑터를 import하지 않는 로직 코드 |
| `tools/smpl_body.py` | 모델 → A자세 → 측정 → `body_apose.obj`, `measurements.json`, `debug_front.png` |

SMPL 모델을 받는 방법과 라이선스는 4절에 있다. 모델 파일은 커밋하지 않는다(`models/`는 `.gitignore`).

**모델 파일 읽기**
- 공식 `.pkl`에는 chumpy 객체가 섞여 있다. chumpy는 오래돼 새 Python에서 설치가 잘 안 되므로, 제한된 언피클러로 배열만 꺼낸다.
- numpy·scipy.sparse 외의 클래스는 불러오지 않는다. pickle을 통한 임의 코드 실행을 막으려는 것이다.
- `.npz`도 읽는다.
- **실제 파일로 확인했다** (SMPL for Python v1.1.0, 중성·남성·여성)
  - chumpy 객체는 `shapedirs` 하나였다. 상태의 `x`에서 배열을 꺼내 (6890, 3, 300)으로 읽었다(체형 계수 300개).
  - 파일이 가리키는 `scipy.sparse.csc` 경로는 SciPy 2.0에서 없어진다. 그래서 같은 이름의 클래스를 `scipy.sparse`에서 바로 가져온다.

**좌표**: y가 위, z가 앞(몸이 보는 방향), x가 몸의 왼쪽이다. 단위는 미터이고, 치수는 cm로 바꿔 소수 첫째 자리까지 쓴다.

## 2. A자세

- SMPL의 기본 자세는 T자세다. 왼쪽·오른쪽 어깨 관절을 z축으로 각각 −45°·+45° 돌려 팔을 45° 내린다(`--arm-angle`로 바꿀 수 있다).
- 45°는 천 시뮬레이션에서 팔과 몸통 사이에 틈을 두려고 고른 값이다. C의 스파이크 결과를 보고 조정한다.
- OBJ는 미터 단위 그대로 저장한다(SMPL·Blender 기본).

## 3. 측정 정의 (measure_v1)

팀 계약의 측정 위치 measure_v1(`docs/decisions.md` "신체 측정 위치", `Measurements` 필드 설명)을 메시에 옮겼다. 결과 키도 `Measurements` 필드 이름(`height_cm`, `chest_cm`, `waist_cm`, `shoulder_cm`, `arm_length_cm`)과 같다.

| 필드 | measure_v1 | 메시에서 재는 방법 |
|---|---|---|
| `height_cm` | 맨발 바닥부터 정수리까지 수직 높이 | 메시의 가장 높은 점과 가장 낮은 점의 높이 차 |
| `chest_cm` | 가슴이 가장 돌출된 수평 위치의 둘레 | spine3 관절 높이부터 어깨 관절 4cm 아래까지 15단계로 수평으로 자르고, 몸통 단면의 볼록 둘레 중 가장 큰 값 |
| `waist_cm` | 자연 허리 위치의 수평 둘레. 배꼽 둘레와 구분 | spine1~spine3 관절 높이를 15단계로 수평으로 자르고, 몸통 단면의 볼록 둘레 중 **가장 작은 값**(가장 잘록한 곳) |
| `shoulder_cm` | 좌우 어깨끝 기준점 사이의 직선 거리 | 어깨 끝점 사이 직선거리. 어깨 끝점은 SMPL 정점 3011(왼쪽)·6470(오른쪽) |
| `arm_length_cm` | 오른쪽 어깨끝에서 팔꿈치를 거쳐 손목 기준점까지 | **오른쪽** 어깨 끝점 → 오른쪽 팔꿈치 관절 → 오른쪽 손목 관절 거리의 합 |

- **팀 저장소로 옮기며 바꾼 것** (처음에는 A2의 임시 '재는 법'을 따랐다)
  - 허리: spine1 관절 높이(배꼽 높이 근사) → 자연 허리(가장 잘록한 곳)
  - 팔길이: 왼팔 → 오른팔
  - 결과 키: `heightCm` 등 → `Measurements` 필드 이름

- **둘레**: 줄자는 오목한 곳을 건너뛰므로 단면의 볼록 껍질 둘레를 쓴다.
- **팔 정점 제외**: 스키닝 가중치가 가장 큰 관절이 팔인 정점(면)은 몸통 단면에서 뺀다. A자세에서 팔이 겨드랑이 근처 단면에 섞이지 않게 하려는 것이다.
- **측정 자세**: A자세(팔 45° 내림)에서 잰다. 줄자로 잴 때처럼 팔을 내린 자세에 가깝다. T자세에서는 어깨가 올라가 어깨너비가 약 3.5cm 작게 나온다(중성 34.8cm).
- **높이와 단면은 관절·가중치로 정한다**: 가슴·허리 높이와 팔 정점 제외는 모델 파일에 든 관절 회귀 행렬과 스키닝 가중치로 정한다.
- **어깨 끝점만 정점 번호를 쓴다**: 실제 모델로 정점 3011·6470의 위치를 확인했다.
  - 어깨 관절 바로 위 약 5cm에 있다.
  - 좌우가 거울 대칭이다(6mm 이내).
  - 가중치가 쇄골 관절에 가장 크다.
  - 이 확인은 `-m smpl` 테스트에도 넣었다.
- **처음 정의를 바꾼 이유**: 처음에는 '어깨 관절 높이 위에서 가장 바깥 정점'을 어깨 끝점으로 썼다. 실제 모델에서 두 가지 문제가 나와 바꿨다.
  - A자세에서는 위팔 바깥(삼각근)이 잡혀, 팔길이가 47.9cm로 짧게 나왔다.
  - T자세에서는 팔 전체가 그 높이에 있어 손끝이 잡혔다(어깨너비 163cm).
  - '가장 높은 점'(30cm, 승모근 위)이나 '위·바깥 모서리'(T자세에서 틀어짐)도 해 봤지만 맞지 않았다.
- **D3에 미치는 영향**: 측정 정의가 사람이 줄자로 잰 값과 어긋나면, D3이 그 차이만큼 몸을 크거나 작게 만든다. 그래서 4절 실행 뒤 `debug_front.png`로 위치를 눈으로 확인한다.

## 4. 실행 방법과 확인

저장소 `.venv`(Python 3.10 이상)에 선택 의존성 `body`(numpy, scipy, OpenCV)를 함께 설치한다.

```bash
pip install -e ".[dev,body]"
python -m pytest tests/body tests/adapters   # 합성 몸·작은 합성 모델 테스트(모델 파일 불필요)
```

**SMPL 모델 받기**
1. [SMPL 공식 사이트](https://smpl.is.tue.mpg.de)에 가입하고 라이선스에 동의한다. 가입과 동의는 각자 직접 한다.
2. Download 메뉴에서 **SMPL for Python** (v1.1.0)을 받는다.
3. 압축을 풀고 모델 파일(`.pkl`)을 `models/smpl/` 아래에 둔다. 중성 모델을 기본으로 쓰고, 남성·여성 모델은 필요할 때 쓴다. 받은 파일 이름이 다르면 그 이름을 그대로 쓴다.

```text
models/smpl/basicmodel_neutral_lbs_10_207_0_v1.1.0.pkl   # 중성(기본)
models/smpl/basicmodel_m_lbs_10_207_0_v1.1.0.pkl         # 남성(선택)
models/smpl/basicmodel_f_lbs_10_207_0_v1.1.0.pkl         # 여성(선택)
```

공식 `.pkl`에는 chumpy 객체가 들어 있지만 chumpy를 설치할 필요는 없다(1절). 읽기에 실패하면 chumpy를 뺀 `.npz`로 바꿔 써도 된다(키 이름은 같다).

**SMPL 라이선스에서 지킬 것** (비상업적 연구·교육용, [라이선스 전문](https://smpl.is.tue.mpg.de/modellicense.html))
- **각자 받는다**: 라이선스는 1인용이고 파일 공유가 금지돼 있다. 모델을 쓰는 팀원은 각자 가입해 받는다. 다른 PC에서 재현할 때도 마찬가지다.
- **커밋하지 않는다**: 모델 파일은 저장소나 공유 드라이브에 올리지 않는다.
- **논문을 인용한다**: 보고서·발표에 Loper et al., "SMPL: A Skinned Multi-Person Linear Model," ACM TOG (SIGGRAPH Asia) 2015를 적는다.
- **상업적으로 쓰지 않는다**: 상용화하려면 별도 상업 라이선스가 필요하다.

모델을 둔 뒤 실행한다.

```bash
SMPL_MODEL_PATH=models/smpl/basicmodel_neutral_lbs_10_207_0_v1.1.0.pkl python -m pytest -m smpl
python -m tools.smpl_body --model models/smpl/basicmodel_neutral_lbs_10_207_0_v1.1.0.pkl
```

`-m smpl` 테스트는 아래 다섯 가지를 확인한다.
- 모델 배열 크기: 정점 6890, 면 13776, 관절 24
- 좌우 방향: 왼쪽 관절이 +x
- A자세: 손목이 어깨보다 아래·바깥
- 어깨 끝점 정점이 좌우 대칭이고 어깨 관절 2~10cm 위에 있는지
- 평균 체형 치수가 넓은 성인 범위 안에 있는지, betas를 바꾸면 치수가 바뀌는지

**합성 몸 검증 결과** (원기둥으로 만든 몸, 정답을 식으로 계산)

| 치수 | 측정값 | 정답 |
|---|---|---|
| 키 | 170.0 cm | 170.0 cm |
| 가슴둘레 | 94.2 cm | 반지름 15cm 64각형 둘레 94.2 cm |
| 허리둘레 | 81.6 cm | 반지름 13cm 64각형 둘레 81.6 cm |
| 어깨너비 | 42.0 cm | 어깨 끝점으로 둔 두 점 (±21cm) 사이 42.0 cm |
| 팔길이 | 59.3 cm | 오른쪽 어깨 끝점~팔꿈치 32.3 + 아래팔 27.0 cm |

합성 몸 테스트에는 measure_v1을 따르는지 보는 두 가지가 더 있다.
- 배꼽 높이(spine1)가 볼록한 배에 걸리는 몸에서, 허리를 그 위의 가장 잘록한 곳에서 잰다.
- 오른쪽 아래팔만 짧게 바꾸면 팔길이가 그만큼 줄어든다(왼팔이 아니라 오른팔을 잰다).

파란 선은 가슴·허리 측정 높이이고, 초록 점과 선은 어깨 끝점과 어깨너비다.

- **측정 위치**: 중성 모델의 `debug_front.png`로 눈으로 확인했다.
  - 가슴선은 겨드랑이 바로 아래에 있다.
  - 허리선은 배꼽보다 위, 몸통이 가장 잘록한 곳에 있다(spine1보다 약 6.7cm 위).
  - 어깨 끝점은 어깨 위·바깥 모서리에 있다.
- **허리가 3~4cm 줄었다**: 배꼽 높이 대신 가장 잘록한 곳을 재기 때문이다.
- **팔길이가 1~1.3cm 늘었다**: SMPL 평균 체형도 좌우가 완전히 같지 않다. 오른쪽 아래팔(팔꿈치~손목 관절)이 왼쪽보다 0.3~0.7cm 길고, A자세에서 어깨 끝점~팔꿈치도 오른쪽이 0.5~0.6cm 길다.
- **값의 크기**: 어깨너비와 팔길이는 흔히 알려진 성인 범위와 비슷하다(어깨 끝 뼈 사이 직선 36~41cm, 팔길이는 키의 약 0.31배). 둘레는 SMPL 평균 체형이 약간 큰 편이다.
- **`-m smpl` 테스트**: 중성·남성·여성 모델 모두 5개 통과
  - 모델 배열 크기
  - 좌우 방향과 A자세
  - 평균 체형 치수 범위
  - 어깨 끝점의 대칭·위치
  - betas를 바꾸면 치수가 바뀌는지
- **C에게 넘길 OBJ**: `artifacts/body/basicmodel_neutral_lbs_10_207_0_v1.1.0-mean/body_apose.obj`(미터 단위, 정점 6890). 팀 공유 드라이브에 올려 넘긴다. SMPL 라이선스에 생성 메시를 공유하는 조항은 따로 없다. C가 직접 몸을 만들게 되면 C도 SMPL에 가입한다.

## 6. 열린 질문과 다음 단계

- **어깨너비 기준이 서로 다르다 (B·팀 결정 필요)**
  - 몸의 어깨 끝 뼈 사이 직선거리는 평균 36~40cm다.
  - 옷 어깨너비(솔기~솔기)는 보통 43~50cm다.
  - 그런데 지금 판정 기준(`fit_rules_v0`의 어깨 경계 −1~2cm)은 몸 어깨너비가 옷과 비슷하다고 가정한다.
  - measure_v1은 어깨를 직선거리로 정했으므로, 측정을 바꾸지 않고 판정 경계를 이 차이에 맞춰야 한다.
  - 이 항목은 `docs/decisions.md` "아직 정할 것"의 '어깨 기준표 경계'에 올라가 있다(C3 실측 뒤 `fit_rules_v1`에서 조정).

- 어깨 끝점이 삼각근 바깥쪽에 잡혀 실제 어깨뼈 끝보다 넓게 나오는지 확인한다.
- 허용 오차(`docs/decisions.md` "허용 오차")가 정해지면 D3 판정에 쓴다.
- **D3(사용자 치수에 맞춘 몸 생성)**: 이 측정 함수와 목표 치수의 차이를 줄이도록 betas를 최적화한다.
  - `BodyMeasurementsCm.fitted_metrics(target)`가 B1 `BodyBuilder` 포트의 지표 키(`fitted_height_cm` 등 5개와 `max_abs_error_cm`)를 만든다. D3 어댑터가 `PortResult.metrics`에 그대로 쓴다.
  - 허용 오차를 넘으면 `BODY_FIT_NOT_CONVERGED`로 실패한다(포트 설명).
